# 상품 관리 기능 명세

## 공통 레이아웃

```
┌──────────┬──────────────────────────────────────────────┐
│ Sidebar  │ Header: Breadcrumb ·············· (데모 안내 뱃지) │
│ 240px    ├──────────────────────────────────────────────┤
│          │ PageHeader: 제목 + 설명 ······ [주요 버튼]      │
│ 상품 관리 ●│                                              │
│ 주문  준비중│  본문 (최대 폭 1200px, 배경 #F5F8FC)           │
│ 재고  준비중│                                              │
│ 인보이스 준비중                                            │
│ AI 발주 준비중                                             │
└──────────┴──────────────────────────────────────────────┘
```

- 준비 중인 메뉴: 회색으로 표시하고 "준비 중" 뱃지를 붙인다. 링크를 걸지 않고 `aria-disabled`를 지정한다.
- 태블릿(1024px 미만): 사이드바를 아이콘만 남기거나 접는다. 모바일(768px 미만): 햄버거 버튼으로 여는 드로어로 바꾼다.
- `/`는 `/products`로 이동시킨다. 랜딩페이지 이식은 Figma 자료를 받은 뒤 결정한다.

## 1. `/products` 상품 목록

| 구역 | 내용 |
|---|---|
| PageHeader | "상품 관리", 전체 n개, **[+ 상품 등록]** → `/products/new` |
| 툴바 | Search Input(상품명·SKU), 카테고리 Filter, 재고 Filter(전체/재고 부족), 정렬(최신 등록순/가격 낮은순/가격 높은순), 필터 초기화 |
| Product Table | 이미지 썸네일, 상품명+SKU, 카테고리, 판매가, 재고(현재/안전), 상태 뱃지, 수정일 → 행을 클릭하면 상세로 이동 |
| Pagination | 한 페이지에 10개, 이전/다음 + 페이지 번호, "n–m / 전체 N" 표시 |
| 모바일 | 테이블 대신 카드 목록으로 표시 |

**URL 파라미터**

| 키 | 값 | 기본값 |
|---|---|---|
| `q` | 검색어 (최대 50자) | 없음 |
| `category` | 카테고리 목록 중 하나 | 전체 |
| `stock` | `low` | 전체 |
| `sort` | `latest` · `price_asc` · `price_desc` | `latest` |
| `page` | 1 이상 정수 | 1 |

- 검색어는 300ms 동안 입력이 멈추면 URL에 반영한다. 필터가 바뀌면 `page`는 1로 돌린다.
- 검색어에 들어 있는 `%`, `_`, `,`, `(`, `)`는 검색 문법으로 해석되지 않도록 서버에서 처리한다.
- 잘못된 파라미터는 기본값으로 처리한다. `page`가 마지막 페이지보다 크면 마지막 페이지로 이동시킨다.

**상태 처리**

| 상태 | 화면 |
|---|---|
| 로딩 | 테이블 Skeleton 10행 (`loading.tsx` 또는 Suspense) |
| 상품 0개 | Empty State: "등록된 상품이 없습니다" + [상품 등록] |
| 검색 결과 0개 | Empty State: "조건에 맞는 상품이 없습니다" + [필터 초기화] |
| 오류 | Error State: "상품 목록을 불러오지 못했습니다" + [다시 시도] (`error.tsx`) |

## 2. `/products/new` 상품 등록

Product Form의 구역:

1. **기본 정보**: 상품명*, SKU*, 카테고리, 판매 상태(기본 판매중), 설명
2. **가격**: 판매가*, 원가. 두 값을 모두 입력하면 마진율을 보여준다(보기용).
3. **재고**: 현재 재고*, 안전재고*
4. **이미지**: 파일 선택(끌어다 놓기 포함), 미리보기, 제거 버튼

- 버튼: [취소] → 목록, [등록하기]
- 저장 중에는 버튼을 비활성화하고 "저장 중…"으로 표시한다. 중복 제출을 막는다.
- 성공: `/products/[id]`로 이동하고 Toast "상품이 등록되었습니다".
- 실패: 입력 내용은 그대로 유지한다. 항목별 오류는 입력창 아래에, 전체 오류는 폼 위쪽에 표시한다.
- 작성 중에 페이지를 떠나려 하면 "저장하지 않은 내용이 있습니다" 경고를 띄운다.

## 3. `/products/[id]` 상품 상세

- Breadcrumb: 상품 관리 › 상품명
- 왼쪽: 이미지(없으면 기본 플레이스홀더). 오른쪽: 상품명, SKU, 상태 뱃지, 카테고리
- 정보 카드: 판매가, 원가, 마진율, 현재 재고, 안전재고, 설명, 등록일, 수정일
- 버튼: [수정] → `/edit`, [삭제] → Confirmation Dialog
- 로딩: 상세 Skeleton
- **잘못된 ID**: UUID 형식이 아니거나 해당 상품이 없으면 `notFound()`를 호출해 "상품을 찾을 수 없습니다" 화면과 [목록으로] 버튼을 보여준다.

## 4. `/products/[id]/edit` 상품 수정

- 등록과 같은 Product Form을 쓰고, 기존 값을 미리 채운다.
- 숨김 필드로 `updated_at`을 함께 보낸다. 그 사이에 다른 곳에서 수정됐다면 "다른 곳에서 먼저 수정되었습니다. 새로고침 후 다시 시도해 주세요"를 표시한다.
- 성공: 상세 페이지로 이동하고 Toast "수정되었습니다". 수정일이 갱신된 것을 확인할 수 있다.
- 없는 상품이면 `notFound()`.

## 5. 삭제

1. [삭제] → Dialog: "‘상품명’을 삭제할까요? 이 작업은 되돌릴 수 없습니다." [취소] [삭제]
2. 처리 중에는 버튼을 비활성화한다. Esc 키나 바깥 클릭은 처리 중에 막는다.
3. 성공: `/products`로 이동하고 Toast "삭제되었습니다". 목록에서 바로 사라진다.
4. 이미 삭제된 상품이면 Toast "이미 삭제되었거나 존재하지 않는 상품입니다"를 띄우고 목록으로 이동한다.
5. 연결된 이미지 파일도 삭제한다. 실패해도 상품 삭제는 유지하고 서버 로그에 기록한다.

## 입력값 검증 규칙 (`features/products/schema.ts`)

| 필드 | 규칙 | 오류 문구 |
|---|---|---|
| name | 공백 제거 후 1~100자 | "상품명을 입력해 주세요" / "100자 이하로 입력해 주세요" |
| sku | 대문자 변환, `^[A-Z0-9][A-Z0-9_-]{1,39}$` | "영문 대문자, 숫자, -, _ 로 2~40자 입력해 주세요" |
| category | 정의된 목록 또는 빈 값 | "카테고리를 목록에서 선택해 주세요" |
| price | 필수, 원 단위 정수, 0 이상, 100억 원 미만. 소수점은 반올림하지 않고 거부 | "판매가를 입력해 주세요" / "판매가는 숫자로 입력해 주세요" / "판매가는 0원 이상이어야 합니다" / "판매가는 원 단위 정수로 입력해 주세요 (소수점은 입력할 수 없습니다)" |
| cost | 빈 값 또는 price와 같은 규칙 | 같은 문구 ("원가는 …") |
| stock_quantity | 필수, 0 이상 정수, 2,147,483,647 이하 | "현재 재고는 0개 이상이어야 합니다" / "현재 재고는 소수점 없이 정수로 입력해 주세요" |
| safety_stock | 0 이상 정수 | 위와 같음 |
| status | `active` / `inactive` | |
| description | 2000자 이하 | |
| image_path | 빈 값 또는 `products/<uuid>.(jpg/png/webp)` | "이미지 정보가 올바르지 않습니다" |

- 쉼표가 들어간 금액(`12,000`)은 쉼표를 지운 뒤 검사한다.
- **브라우저 검증은 편의용이고, 서버의 Server Action에서 같은 스키마로 반드시 다시 검증한다.**

## 서버 오류 → 사용자 안내

| 원인 | 판단 기준 | 안내 |
|---|---|---|
| SKU 중복 | Postgres `23505` + `products_sku_key` | SKU 칸에 "이미 사용 중인 SKU입니다" |
| DB 제약 위반 | `23514` | "입력값을 다시 확인해 주세요" |
| 상품 수 한도 | `PRODUCT_LIMIT_REACHED` | "데모 환경은 최대 300개까지 등록할 수 있습니다" |
| 요청 과다 (선택) | quota false | "요청이 너무 많습니다. 잠시 후 다시 시도해 주세요" |
| 네트워크 오류 | 브라우저에서 요청 자체가 실패 | "네트워크 연결을 확인하고 다시 시도해 주세요" (입력값 유지) |
| 기타 | | "일시적인 오류가 발생했습니다" (자세한 내용은 서버 로그에만 남김) |

## Server Action 결과 형식

```ts
type ActionResult<T = void> =
  | { ok: true; data: T }
  | { ok: false; message: string; fieldErrors?: Partial<Record<string, string>> }
```

## 성공 Toast 전달 방식

Server Action이 `redirect()`하기 직전에 짧게 유지되는 flash 쿠키(`toast=created` 등)를 저장한다. 이동한 페이지의 Toast 컴포넌트가 이 쿠키를 읽어 메시지를 띄우고 바로 지운다. URL에 흔적이 남지 않는다.
